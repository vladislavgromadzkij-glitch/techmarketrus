# techmarketrus / Core Architecture Specification

**Версия спецификации:** 1.0.0-MVP

**Стек:** C++20, Qt 6.5+ (Quick Controls Basic), CMake 3.21+, Linux (Fedora 40+)

**Назначение:** Архитектурный регламент интерфейсов, потоков данных (Data Flow) и контрактных связей ядра приложения.

---

## 1. Миссия и концепция платформы

Платформа **TechMarket** — специализированный аппаратно-технический маркетплейс и биржа оборудования, спроектированная под требования инженерного сообщества и правовые нормы РФ.

В отличие от потребительских маркетплейсов широкого профиля (Ozon, Wildberries) и классических досок объявлений (Авито), TechMarket решает фундаментальные проблемы инженерного рынка:

* **Отсутствие скрытых комиссий и навязанных услуг:** Прозрачный процессинг без платного продвижения мусорных объявлений.
* **Параметрическая инженерная фильтрация:** Поиск по ревизиям кристаллов, стандартам ГОСТ / ТР ТС, пропускной способности шин, полосе пропускания, частотам АЦП/ЦАП и форм-факторам, а не по маркетинговым заголовкам.
* **Разделение правовых режимов участников:** Четкая дифференциация B2C-поставок нового оборудования (с обязательной верификацией сертификатов ЕАЭС) и C2C-оборота б/у приборов, микросхем и донорских плат.
* **Инженерный контроль качества (Health Status):** Обязательная структурированная фиксация дефектов и работоспособности б/у лотов, исключающая покупку неисправного оборудования под видом рабочего.
* **Оптовая ступенчатая тарификация (B2B/Small-Wholesale):** Нативная поддержка многоуровневых цен в зависимости от объема партии прямо в карточке лота.

### Блок 1. Модель каталога и фильтрации (`CatalogModel` + `ProductFilterProxyModel`)

* **Роль:** Хранение кэша карточек товаров в памяти, виртуализация выборки для UI и локальная фильтрация без спама запросами к серверу.
* **Входные данные:** `QList<ProductItem>` от оркестратора при гидратации данных.
* **Обработка:** Сохранение элементов во внутренний вектор. Предоставление именованных ролей (`title`, `basePrice`, `specsPreview`, `hasEac`, `healthStatus`, `defectDesc`, `wholesaleTiers`). Прокси-модель (`QSortFilterProxyModel`) фильтрует срез по строке поиска и флагам категорий.
* **Выходные данные:** `QVariant` для отображения в делегатах `ListView` / `GridView`.
* **Исходящие сигналы:**
* `beginResetModel()` / `endResetModel()` — полная перезагрузка витрины.
* `dataChanged(topLeft, bottomRight)` — точечное обновление лота (изменение цены/остатка).



---

### Блок 2. Сетевой транспорт (`NetworkClient`)

* **Роль:** Изолированный асинхронный ввод-вывод по протоколу HTTP REST (JSON) с локальным сервером `[http://127.0.0.1:8080/api/v1/](http://127.0.0.1:8080/api/v1/)`.
* **Входные методы:**
* `fetchLots(int page, int limit)`
* `sendNewLot(const QJsonObject &lotData)`
* `sendOrder(const QJsonObject &orderData)`
* `sendChatMessage(int dialogId, const QString &text, double offerPrice)`


* **Обработка:** Сериализация в JSON, отправка через `QNetworkAccessManager`, валидация HTTP-кодов ответа (200, 201, 422), парсинг сырых байт ответа в `QJsonDocument`.
* **Выходные данные:** Распарсенные JSON-структуры, передаваемые оркестратору через сигналы.
* **Исходящие сигналы:**
* `lotsLoaded(const QJsonArray &rawLots)` — массив лотов от сервера.
* `lotPublished(int lotId)` — подтверждение публикации объявления.
* `orderConfirmed(int orderId, const QString &trackingCode)` — подтверждение регистрации заказа.
* `chatMessageDelivered(int dialogId, int messageId)` — подтверждение доставки сообщения.
* `networkError(const QString &endpoint, const QString &errorMsg)` — сетевой сбой.



---

### Блок 3. Публикация, правовой комплаенс РФ и AI (`ListingEditor`)

* **Роль:** Бизнес-валидация создаваемых объявлений в соответствии с законами РФ и предварительная обработка карточки нейросетью.
* **Входные данные:** Статус продавца (`SellerLegalStatus`), признак своего производства (`bool isSelfMade`), ИНН/ОГРН, номер сертификата ЕАЭС, фото (`QStringList`), сырое описание (`QString`).
* **Обработка:**
* *Правовой фильтр:*
* Самозанятый (422-ФЗ) + `isSelfMade == false` $\rightarrow$ Отказ (запрет перепродажи чужого заводского оборудования).
* Юрлицо/ИП (ЗоЗПП) + Новый товар + отсутствие номера ТР ТС 004/020 $\rightarrow$ Отказ.
* Физлицо (ГК РФ) + Б/У лот $\rightarrow$ Обязательная проверка заполнения полей `HardwareHealth` и `defectDescription`.


* *AI-модуль:* Экстракция ключевых характеристик в строку `techSpecsPreview` и проверка по стоп-листу (ст. 138.1 УК РФ — СТС НПИ, глушилки/РЭБ без лицензий).


* **Выходные данные:** Валидированный объект `ProductItem` для отправки на публикацию.
* **Исходящие сигналы:**
* `validationPassed(const ProductItem &item)` — лот проверен и допущен к публикации.
* `validationFailed(const QString &targetField, const QString &legalClauseWarning)` — отказ с юридическим обоснованием.
* `aiAnalysisFinished(const QString &generatedSpecs, const QString &suggestedCategory)` — характеристики распознаны.



---

### Блок 4. Менеджер заказов и логистики (`OrderManager`)

* **Роль:** Расчет тарифов доставки, назначение защитной упаковки под технические грузы и подготовка комплекта закрывающих документов.
* **Входные данные:** `lotId`, количество, габариты/вес, адрес назначения, тариф Яндекса (ПВЗ / Курьер Экспресс), категория оборудования.
* **Обработка:** Расчет финальной стоимости доставки. Автоматическое добавление опции **«Антистатический ESD-пакет»** для полупроводников и плат либо жесткой обрешетки для тяжелого серверного железа. Формирование списка документов: УПД (для B2C) или электронный акт с фиксацией дефектов (для C2C).
* **Выходные данные:** Заказ, переданный в сетевой шлюз, и сводка по стоимости для окна оформления.
* **Исходящие сигналы:**
* `deliveryCalculated(double totalCost, double deliveryCost, const QString &etaDate, const QString &appliedPackage)` — расчет завершен.
* `orderPlaced(int orderId, const QString &trackingNumber, const QStringList &requiredDocs)` — заказ принят в обработку.



---

### Блок 5. Движок инженерных чатов и торга (`ChatManager`)

* **Роль:** Обмен сервисными и пользовательскими сообщениями, привязанными к лотам, и сопровождение протокола торга.
* **Входные данные:** `lotId`, `dialogId`, текст сообщения, сумма встречного предложения.
* **Обработка:** Регистрация веток диалогов. Перевод сделки по лоту в статус торга (`OfferPending`). Блокировка/активация кнопок согласия вендора.
* **Выходные данные:** Обновленная история переписки и статус оффера в UI.
* **Исходящие сигналы:**
* `messageReceived(int dialogId, const QString &sender, const QString &text, const QString &time)` — входящее сообщение.
* `priceOfferStateChanged(int dialogId, double newPrice, int offerState)` — обновление статуса встречной цены (Ожидает / Принято / Отклонено).



---

### Блок 6. Оркестратор ядра (`CoreApplicationManager`)

* **Роль:** Центральный контроллер (Mediator / Event Router). Владеет экземплярами всех подсистем, инициализирует их, провязывает сигналы и слоты между ними. Не содержит внутри себя UI-логики.
* **Входные данные:** Сигналы от всех подсистем приложения.
* **Обработка:** Трансляция данных между несвязанными модулями (например, перенаправление ответа от `NetworkClient` в метод загрузки `CatalogModel`). Экспорт фасадов в QML-движок.
* **Выходные данные:** Вызовы управляющих методов моделей и сетевого слоя.
